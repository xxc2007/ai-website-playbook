# Security Review Checklist（安全审查清单）

> 每次生成/改动代码、发布、清理之前过一遍。约束以「验收条件」口径书写：直接按约束实现，不满足即视为未通过。

## A. 生成前扫描

- [ ] 本机安全扫描完整通过，拿到扫描 seal（如 sha256 摘要）。
- [ ] 扫描器报资源不足（如 `scanner_enobufs`）或任何「未得出完整结论」状态时：**不得宣称项目级安全结论**，不得触发真实推送/发布。
- [ ] 独立深度扫描的结论如实记录（seal、verdict、依赖告警数），不夸大为整体安全认证。

## B. 服务端请求 URL 校验（SSRF）

- [ ] 仅允许 `http` / `https` 协议。
- [ ] 发请求前校验 host：拒绝 `localhost`、环回地址、私有网段（10/8、172.16/12、192.168/16）、保留地址（169.254/16、::1 等）。
- [ ] 校验在**发请求前**完成，且对重定向后的目标同样生效（或干脆禁止跟随重定向到未校验目标）。

## C. 数据库查询

- [ ] 所有外部输入使用参数绑定（prepared statement / 占位符）。
- [ ] 不得用字符串拼接、`format`、f-string 组装 SQL——包括 ORDER BY、表名等动态片段（改用白名单映射）。

## D. 凭据管理

- [ ] 凭据只从环境变量或密钥服务读取；源码、示例、测试**不含可用凭据字面量**。
- [ ] 密钥不进仓库、文档、日志、提交信息、聊天输出。
- [ ] 服务器密钥统一在 `/opt/<app>/.env`（root 权限）；辅助配置在 `/etc/<app>/`；本机副本放加密 vault 目录（不在仓库树内）。
- [ ] 公开文档/报告描述密钥位置时用「服务器 .env」级别的模糊表述，不写具体文件名组合（凭据位置本身也是敏感信息）。
- [ ] 删除任何 vault/备份目录前，先核对其中的凭据是否已轮换——**轮换是删除的前置条件**。
- [ ] env 备份不放在代码目录（放 `$APP_HOME` 上层或专用配置目录）。

## E. 仓库与发布包卫生

- [ ] `.gitignore` 覆盖：`.env`、`.env.*`、`.data/`、密钥文件、工作区诊断产物（`_diag/logs/*.log` 等）。
- [ ] 发布包（`git archive`）排除清单：`node_modules/ .data/ .env .git`。
- [ ] **内网字面量护栏**：源码与测试中不出现真实私有 IP；测试要用内网地址语义时，用 RFC 5737 文档段（`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24`）。若发布脚本带字面量护栏，护栏拒绝既有提交时先出 PR 改字面量或加排除，不带病发布。
- [ ] CI 定义双份逐字节同步（`diff` 核对），防两处定义漂移被利用。
- [ ] 审计/事故/清理文档放 `docs/history/`（只增不改）；**公开仓库不写凭据位置与内网拓扑**。

## F. 后台门禁验收

```bash
# 未登录访问后台 → 302 到登录页
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' https://example.com/<app>/admin
# 未登录访问后台 API → 401
curl -s -o /dev/null -w '%{http_code}\n' https://example.com/<app>/api/admin/nav-counts
```

- [ ] 两个状态码实测通过，不靠感觉。
- [ ] 会话 cookie 属性（HttpOnly、Secure、SameSite）与过期策略有明确配置并写在文档里。

## G. 维护锁协议

- [ ] 锁以 `O_CREAT | O_EXCL` 原子取得；文件内容含 owner、会话标识、时间戳。
- [ ] 发现非自身 owner、或无法确认排空时**立即停止维护**。
- [ ] 禁止按时间推算、SSH 断连、PID 消失、数据库无连接等间接信号推断排空并删锁。
- [ ] 高风险维护（需重启数据库/共享服务的变更）必须：维护锁 + 低流量窗口 + 资源门槛满足 + 逐条确认，四者齐备。

## H. 清理安全审查

每条候选按四元组评审（target / why / risk / rollback），**只出清单，逐条确认后执行**：

- [ ] 零引用判定有 `git grep` 证据，且区分历史文档命中与功能引用。
- [ ] 服务器侧候选有现场实测（监听端口、systemd/cron 引用 grep、目录 mtime 对账）。
- [ ] 风险评级与治理文档对齐，不私自降级；「是否仍有人工调用」只有主人知道 → 标 `requiresManual`，只提案不判定。
- [ ] archive 语义：移出活动树 + 外部留一份 + git 历史留一份（不是 `git mv` 进仓库归档目录）。
- [ ] 删除前先打包留底（如 `tar czf /opt/<app>/archive/stray-scripts-<日期>.tar.gz …`），tar 包即回滚。
- [ ] 红线复查：无 `docker compose down -v`；删库前有 `pg_dump`；无整体覆盖远端/生产；无夹带无关改动。
- [ ] 可再生缓存与不可再生数据分账；日志只控量（`journalctl --vacuum-size`）不删除。
- [ ] 没有可用入口的节点如实标「未盘点」；密钥面未读的文件不列为候选——宁漏不猜。

## I. 审计文档纪律

- [ ] 历史文档只增不改（审计、事故记录、执行台账）。
- [ ] 没实际跑过的检查，报告里写「未验证」，不写成已通过。
- [ ] 报告中的每条结论带证据（命令与输出、file:line、实测时间）。
- [ ] 运行优先级约束写入运维文档通俗版：读者页面可用性优先于回填/清理/诊断；维护避开读者高峰；不靠清未知回执、绕保护、盲目提并发制造吞吐。

## J. 报告诚信

- [ ] 推送/发布结果按四端身份核对口径给结论（本地 HEAD = GitHub = 每台 `.release` 完整 40 位 = `health.release`），不凭脚本退出码。
- [ ] 失败如实报：卡在哪一步、错误原文、已尝试的处置；不假推、不假绿。
- [ ] 需要人工逐条确认的事项列成清单交 owner（needsUser），不代签、不默认同意。
- [ ] 真实浏览器验收对生产只读导航，严禁误触「重建/清理/删除/发布/回填/重置」类按钮；写路径验证一律在 `_test` 环境。
